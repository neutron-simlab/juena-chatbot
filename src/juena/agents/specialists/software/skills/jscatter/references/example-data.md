# JScatter bundled example data

JScatter ships example datasets inside the installed package, so they are
available in the sandbox with no network access and no staged upload. Use them
for demonstrations, for reproducing a documented workflow, and for checking that
a model or fit behaves before applying it to the user's own data.

**Never present example data as the user's data.** If the user supplied files,
use those. If they asked for a demonstration and none was supplied, say plainly
which bundled dataset you used.

## Locating the files

```python
import jscatter as js
js.headless(True)

path = js.examples.datapath            # directory holding every file below
data = js.dL(js.examples.datapath + '/exampledata.dat')
```

`js.examples.datapath` resolves inside the installed package. Do **not** build a
path under `/repos/jscatter/...` — that route exists only for the read tools and
is not mounted in the execution container.

Everything below was verified against the installed baseline, JScatter
`1.9.0.1`. Confirm with `js.__version__` and re-check if it differs.

### SAXS line-collimation files (`.pdh`)

These need explicit column and header handling — a plain `js.dL` fails:

```python
empty = js.dA(js.examples.datapath + '/buffer_averaged_corrected_despiked.pdh',
              usecols=[0, 1], lines2parameter=[2, 3, 4])     # (2, 2057)
beam  = js.dA(js.examples.datapath + '/BeamProfile.pdh',
              usecols=[0, 1], lines2parameter=[2, 3, 4])     # (2, 2084)
```

Also present: `emptybeam_averaged_corrected_despiked.pdh`,
`emptycell_305mm_averaged_corrected_despiked.pdh`.

### Raw QENS files (`.inx`)

`Vana.inx.gz` (vanadium), `ADH.inx.gz` (alcohol dehydrogenase), and `D2O.inx.gz`
are raw instrument format. A plain `js.dL` fails on them. **There is no
`js.readinx`** — the `readinx` seen in the JScatter documentation is a helper the
user is expected to write. The working call is:

```python
adh = js.dL(js.examples.datapath + '/ADH.inx.gz',
            block=' 563 ',                      # spaces matter: marks each block start
            usecols=[1, 2, 3],                  # skip the per-line numbering
            lines2parameter=[-1, -2, -3, -4])   # capture the header values
# → 16 sets of (3, 560), energy transfer -22.3 … 22.4 µeV
```

The `block` string is the channel count and **differs per file**: `' 562 '` for
`Vana.inx.gz`, `' 563 '` for `ADH.inx.gz`. If the block string is wrong the read
fails or returns nothing — check the file's own header rather than guessing.
`D2O.inx.gz` does not read with either block value; treat it as needing its own
inspection, and prefer `Vana_fitted.inx.gz` when you just need a resolution.

### Known unusable in the sandbox

`dlsPolymerSolution.txt` is a Zetasizer Nano export that must be read with
`js.dls.readZetasizerNano(..., NANOlocale=['de_DE', 'UTF-8'])`. That German
locale is not installed in the execution container, so the call raises
`Error unsupported locale setting`. Do not present a DLS/CONTIN demonstration
from this file. Say the bundled DLS example cannot be loaded here, and ask the
user to supply their own correlation data.

## Checklist before using a bundled file

1. Confirm `js.__version__` and that `js.examples.datapath` exists.
2. Load the file and print its shape, column names, and attributes **before**
   modelling — do not assume the table above is still exact.
3. Check whether errors are present (`hasattr(data, 'eY')`); several files have
   none, which changes how a fit should be weighted.
4. Say in the report which bundled file you used and that it is JScatter's own
   example data, not the user's measurement.
